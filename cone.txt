EXPLORATION GAME - SIZE PALIER ROADMAP
=======================================

PROJECT: Convert fluffy-space-chainsaw into modular exploration game
CONSTRAINT: Iterative growth through base28 → base44x48 → base64 paliers

=== PALIER 1: BASE28 ===
Grid Size: ~28x28 cells
Scope: Minimal viable exploration game
Features:
  - Single map layout
  - Basic tile system (. # S O)
  - Player movement & simple navigation
  - Core game loop

Deliverables:
  - map[28][28] data structure
  - Tile renderer
  - Player controller
  - Basic collision detection

=== PALIER 2: BASE44x48 ===
Grid Size: 44x48 cells
Scope: Expanded exploration with better level design
Features:
  - Multiple room/zone system
  - Enhanced tile variety
  - Room transitions
  - Environmental interaction basics
  - AI-driven refactoring from base28

Deliverables:
  - map[48][44] data structure
  - Room manager
  - Transition logic
  - Enhanced tile mechanics
  - Documentation: docs/formulaire_github_base44x48.md

=== PALIER 3: BASE64 ===
Grid Size: 64x64 cells (or larger dynamic)
Scope: Full exploration game with advanced features
Features:
  - Large procedural/handcrafted worlds
  - Advanced NPC systems
  - Quest/dialogue systems
  - Inventory & item mechanics
  - Save/load systems
  - Advanced visual polish

Deliverables:
  - Dynamic map system
  - NPC/quest framework
  - Persistence layer
  - UI/UX polish

=== KEY PRINCIPLES ===
- Each palier is backward compatible (can play base28 within base44x48 bounds)
- Code should be modular and refactorable via AI prompts
- Track "found/built" lines in PRs to understand codebase evolution
- Use French documentation for clarity with international AI tools
- Every PR should map to a specific palier stage
